# Implementation reference

This directory describes how the project currently works: commands, configuration contracts, data flows, defaults, and limitations. It starts empty apart from this note. Add documents only when actual project behavior needs explanation.

Link descriptions to the code, configuration, and tests that support them. These descriptions can become outdated; they are not requirements to preserve a bug. Durable requirements belong in `AGENTS/CONVENTION/`, usage guidance for humans belongs in component READMEs, and temporary findings belong in the session files one level up.

When adding a reference, link it from the relevant convention or the task guidance in [AGENTS.md](../../AGENTS.md). Update it when the implementation changes, and state the scope of anything not yet verified. Do not copy client details, example findings, or assumptions from another project to fill this directory.
